## 1. 通用约定

### 1.1 Base

- `http://127.0.0.1:8793`
- 全部接口默认 `Content-Type: application/json; charset=utf-8`
- 时间：ISO 8601，带 `Z` 或 `+08:00`；DB 内部 UTC
- ID：ULID 文本（`cmp_`、`run_`、`goal_`、`evt_` 等前缀用于可读性）

### 1.2 鉴权

除 `/v1/health`、`/docs`、`/openapi.json` 外，全部需要：

```
Authorization: Bearer <LEAD_API_TOKEN>
```

- Token 从 `~/.lead-platform/config.json` 或 `.env` 读取（0600）。
- 常量时间比较；失败返回 `401 UNAUTHORIZED`。
- 一级一期单 token（用户决策）；接口设计预留 `tokenId` 审计字段。

### 1.3 统一 envelope

```json
{
  "ok": true,
  "data": { },
  "meta": {
    "schemaVersion": "1.0",
    "requestId": "req_01J...",
    "timestamp": "2026-11-16T05:30:00.000Z",
    "tookMs": 12,
    "warnings": []
  },
  "error": null
}
```

失败：

```json
{
  "ok": false,
  "data": null,
  "meta": { "schemaVersion": "1.0", "requestId": "req_01J...", "timestamp": "...", "tookMs": 3 },
  "error": {
    "code": "VALIDATION_ERROR",
    "message": "region.province is required",
    "retryable": false,
    "details": { "field": "region" }
  }
}
```

### 1.4 错误码

| code | HTTP | 说明 |
|---|---|---|
| `VALIDATION_ERROR` | 400 | 参数/枚举/区域校验失败 |
| `UNAUTHORIZED` | 401 | Bearer 缺失/错误 |
| `NOT_FOUND` | 404 | 资源不存在 |
| `CONFLICT` | 409 | 状态冲突（如 Goal 已禁用仍触发等） |
| `RUN_IN_PROGRESS` | 409 | 同一 Goal 已有运行中的 Run |
| `QUOTA_EXHAUSTED` | 409 | 探迹额度不足（仅手动解锁接口可能同步返回） |
| `SOURCE_SESSION_INVALID` | 409 | 上游登录失效（采集前预检失败） |
| `SOURCE_UNAVAILABLE` | 503 | 上游客户端不可达/内部错误 |
| `UPSTREAM_RATE_LIMITED` | 429 | 上游限频/风控冷却中 |
| `UNSUPPORTED` | 400 | 该平台不支持该参数（如区县筛选） |
| `INTERNAL_ERROR` | 500 | 未知错误（带 requestId） |

### 1.5 分页

- **游标分页**（`companies`、`changes`、`jobs`、`deliveries`）：`?limit=20&cursor=<opaque>`；响应 `meta.nextCursor` 为 `null` 表示结束。
- 其它列表（`goals`、`runs`、`sources`、`webhooks`）数据量小，使用 `?limit=&offset=`（默认 50）。
- 排序：`companies` 默认 `updated_at DESC, id DESC`；`changes` 按 `seq ASC`。

### 1.6 幂等

- `POST /v1/goals/{id}/run`：同一 Goal 有运行中 Run → `RUN_IN_PROGRESS`。
- `POST /v1/companies/{id}/unlock`：使用 `idempotencyKey`（默认 `<companyId>:<yyyy-mm-dd>`），重复请求返回同一 job。
- 内部解锁调用探迹时也带 `idempotencyKey`，依赖探迹业务幂等（已解锁不扣额度）。

## 2. Goals

### `POST /v1/goals` — 创建 Goal

```json
{
  "name": "河北省-外贸线索",
  "region": { "province": "河北省" },
  "platforms": ["boss", "zhilian", "ali", "mic"],
  "keywords": {
    "boss": ["外贸", "外贸业务员", "外贸经理", "外贸单证员", "国际贸易"],
    "zhilian": ["外贸", "外贸业务员", "外贸经理", "外贸单证员", "国际贸易"],
    "ali": ["machinery", "hardware", "textile"],
    "mic": []
  },
  "maxLeadsPerRun": 2000,
  "dailyLeadLimit": null,
  "schedule": { "cron": "0 2 * * *", "timeZone": "Asia/Shanghai", "timeWindow": "02:00-08:00" },
  "priority": 100,
  "tradeFilter": null,
  "unlockPolicy": {
    "mode": "priority",
    "order": ["recruiting", "paid_member", "customs", "rest"],
    "note": "Q14 待确认；默认按 P0 招聘在招 > P1 付费/认证会员 > P2 有海关记录 > P3 其余"
  },
  "enabled": true
}
```

- `region.cityCodes` 可选（数组，规范化 GB 地级市 code）；缺省表示全省所有地级市。
- `keywords.ali` 为行业关键词（默认集待确认）；`mic` 留空（按省检索）。
- 返回 `201` + Goal 对象（含派生的 `resolvedCities`：该省将实际检索的城市列表与各平台映射值）。

### 其它 Goal 接口

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/v1/goals` | 列表（`?enabled=`） |
| GET | `/v1/goals/{id}` | 详情（含 resolvedCities、最近 runs 摘要） |
| PATCH | `/v1/goals/{id}` | 更新（乐观锁 `version`；schedule/keywords/limits 等） |
| DELETE | `/v1/goals/{id}` | 归档（软删除，保留历史 run/数据） |
| POST | `/v1/goals/{id}/run` | 手动触发，返回 `202` + Run |
| GET | `/v1/goals/{id}/runs` | 该 Goal 的运行历史 |

## 4. Companies

### `GET /v1/companies` — 列表

查询参数：

| 参数 | 说明 |
|---|---|
| `province` / `city` | 规范名或 GB code |
| `platform` | 过滤（至少有一个来源为该平台） |
| `unlockStatus` | `none/pending/waiting_quota/unlocked/failed` |
| `enrichmentStatus` | `discovered/source_detailed/tanji_matched/tanji_enriched/unmatched/failed` |
| `q` | 公司名模糊（LIKE，最小 2 字符） |
| `updatedSince` | ISO 时间；增量同步用 |
| `limit` / `cursor` | 游标分页 |

返回：`data.items[]` 为 CompanySummary（公司主档摘要 + 来源平台列表 + 解锁状态 + 最近变更时间）+ `meta.nextCursor`。

## 5. 变更与事件

### `GET /v1/changes` — 全局增量

| 参数 | 说明 |
|---|---|
| `sinceSeq` | 从该 seq（不含）之后返回；缺省 0 |
| `types` | 逗号分隔事件类型过滤 |

### `GET /v1/events/stream` — SSE

- `text/event-stream`；`?types=` 过滤；`Last-Event-ID` 断点续传（服务端按 seq 补发）。
- 事件 `data` 为上方 envelope JSON；建议消费者持久化 `seq`。

### Webhook

| 方法 | 路径 | 说明 |

| POST | `/v1/webhooks` | 创建订阅 `{url, eventTypes, secret?, description}` |

## 8. CLI 命令树（`lead`）

```bash
# 运行态
lead status [--json]
lead quota [--json]
lead sources [--json]

# Goal
lead goal list
lead goal show <id>
lead goal create --name 河北省-外贸线索 --province 河北省 --platforms boss,zhilian,ali,mic \
                 --cron "0 2 * * *" [--keywords-boss 外贸,外贸业务员,...] [--max-leads 2000]
lead goal update <id> [--enable|--disable] [--cron ...]
lead goal run <id> [--wait]          # 手动触发，--wait 跟随进度

# Run
lead run list [--goal <id>]
lead run show <id>
lead run cancel <id>

# 公司
lead company list [--province 河北省] [--platform boss] [--unlock-status unlocked] [--q 关键词] [--limit 20] [--json]
lead company show <id> [--json]
lead company contacts <id>
lead company changes <id> [--since-version N]
lead company snapshots <id>
lead company rematch <id>
lead company unlock <id>            # 手动优先解锁
lead company platforms <id>        # 各平台卡片
lead company platform <id> <platform>            # 单平台完整档案
lead company jobs <id> <platform> [--status active|closed] [--limit 50]
lead company refresh <id> [--platforms boss,ali] [--kinds profile,jobs]
lead company customs <id>               # 海关画像（Ali/Mic）
lead company customs-refresh <id>       # 手动刷新海关

# 变更 / 事件
lead changes [--since-seq N] [--types company.created,company.updated]
lead events tail [--types ...]      # 跟随 SSE

# Webhook
lead webhook list
lead webhook create --url https://... --events company.created,contact.unlocked
lead webhook delete <id>
lead webhook deliveries <id> [--status dead]
lead webhook replay <id> <deliveryId>

# 任务
lead job list [--status dead] [--stage unlock]
lead job retry <id>

# 管理（P1）
lead admin backup
lead admin purge --dry-run
```

- 所有命令支持 `--json`（输出与 REST `data` 一致）与 `--base-url`（默认 `http://127.0.0.1:8793`）；Token 从 `LEAD_API_TOKEN` / 配置文件读取。

## 10. OpenAPI / 文档生成

- zod schema 为唯一契约源 → 生成 `spec/openapi.json`、`/docs`（自包含 HTML，不依赖外部 CDN）、`/mcp-tools.json`、CLI `--help`。
- CI 命令：`npm run gen && npm run gen:check`；生成物与实现不一致时 `gen:check` 失败。
- 示例值不包含真实公司/联系人数据（脱敏样例）。
