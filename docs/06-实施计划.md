## 1. 阶段划分

### P0 · 文档与契约（本次交付）

- [x] 需求访谈记录、需求规格、架构与数据模型、接口草案、上游对接、部署运维、实施计划
- 出口：用户评审确认；冻结 v1.0 需求基线

### P1 · 骨架与数据层

- 工程：`package.json` / `tsconfig` / Fastify / zod / commander / MCP SDK / vitest
- 配置加载（`.env` + `config.json`）、日志（JSON + 轮转）、错误模型、统一 envelope
- SQLite 连接（WAL）、migration 框架、`001_init` 全部表 + 索引
- 仓库层：goals / runs / companies / jobs / events / snapshots / webhooks / **platform profiles / platform jobs**
- `GET /v1/health`、`GET /v1/status`（骨架）
- 出口：`npm run typecheck && npm test` 通过；`/v1/health` 毫秒级

### P2 · 区域注册表 + 采集

- 内置 GB/T 2260 基线（至少含河北省 11 市）+ `region_platform_map`
- 区域同步：boss / zhilian / ali / mic 字典拉取与映射（失败回退基线）
- **覆盖策略**（Q6 实测校准）：Boss/智联 11 市 × 10 关键词；Ali 地理种子 + 行业×城市 strict 矩阵（实测 2,961，上限约 3.1–3.3k）；Mic 省+11 市关键词全量并集（5,008）
- Run 覆盖度指标：`uniqueCompanies / crossSourceOverlap / coverageByCity / keywordYield`（见 11/12 文档）；河北全量目标 ≥8,500 家（实测基线 9,586）
- Goal CRUD + 校验；Run 创建；scheduler（cron + 手动）
- Source adapters（4 源）+ 令牌桶/限频/受控并发
- Run Orchestrator：平台 × 城市 × 关键词 → 查询；翻页；流式落 `raw_snapshots` + `source_queries` 进度
- 公司初建/来源关联（USCC 提示+名称兜底）
- 出口：手动触发河北 Goal，Run 有平台/城市级进度与覆盖度指标，唯一公司数 ≥8,500（Ali≥2,600 / Mic≥4,500 / 招聘≥2,000）；`raw_snapshots` 快照可追溯；mock 上游集成测试通过

### P3 · 探迹匹配与工商补全

- tanji adapter：search/name、公司详情、联系人（未解锁为空）
- 匹配算法（USCC 优先、名称打分、候选/置信度留痕）
- 公司主档写入 + 去重/合并 + `company.created` / `company.updated` 变更事件
- `unmatched` 重试策略
- `GET /v1/companies`、`/v1/companies/{id}`、`/sources`、`/snapshots`
- 出口：河北 Run 后公司可查详情、匹配留痕；同公司跨平台合并正确（单元测试覆盖）

### P3b · 平台档案、岗位与刷新 worker（v0.2）

- 4 平台档案抓取（Boss/智联详情、Ali 店铺、Mic 店铺）+ `company_platform_profiles` 写入
- Boss/智联全量岗位抓取 + `company_platform_jobs` 生命周期（active/closed/reactivated）
- 平台字段 diff → 公司变更事件 `platforms.<platform>.<field>`；岗位聚合事件
- Refresh Worker：新公司即时、存量招聘每周/店铺每月；全天涓流 + 租约 + 手动 refresh 插队
- 出口：AC-11/AC-12/AC-13 通过；2 万家容量核算脚本（模拟请求量）通过

### P3c · 海关数据补全（v0.3）

- fuma adapter：`POST /v1/customs/query`（accountId、flag 1/2、缓存/权限/错误归一）
- 英文抬头查询 + 名称 token 过滤 + 角色分类（出口商/进口商）+ 样本聚合 + confidence
- `company_customs_profiles` 写入、`customs.updated` 事件、raw_snapshots（**永久压缩归档**，Q7）
- 新公司即时、存量每月刷新；手动 `customs/refresh`；fuma 账号串行限速
- 出口：AC-14/AC-15/AC-16 通过（mock：权限拒绝/无数据/缓存命中；只读 live 样例）

### P4 · 解锁队列与额度

- Unlock Worker：FIFO、idempotencyKey、QUOTA_EXHAUSTED → waiting_quota
- Quota Poller：额度观测、日刷新/结算日恢复、自动续跑
- `unlock_ledger`、联系人入库、`contact.unlocked` 事件
- `GET /v1/quota`、`/v1/jobs`、手动优先解锁/rematch
- 出口：mock 上游模拟额度耗尽/恢复全流程通过（AC-4）

### P5 · 变更日志、事件与查询完善

- `GET /v1/companies/{id}/changes`（字段级、版本聚合，含平台字段路径）、`GET /v1/changes?sinceSeq=`
- `GET /v1/companies/{id}/platforms`、`/platforms/{platform}`、`/platforms/{platform}/jobs`、`/platforms/{platform}/changes`、`POST /companies/{id}/refresh`
- `GET /v1/companies/{id}/customs`、`POST /v1/companies/{id}/customs/refresh`
- Webhook 订阅 CRUD + HMAC 签名投递 + 重试/死信/重放（含 `platform.profile.updated` / `platform.jobs.updated` / `customs.updated`）
- SSE `/v1/events/stream`（Last-Event-ID 续传）
- `GET /v1/runs`、`/v1/stats`、`/v1/sources` 完善；`/v1/status.alerts`、`/v1/status.refresh`
- 出口：AC-5/AC-6/AC-11/AC-12/AC-14 通过；变更不漏不重（单元 + 集成测试）

### P6 · 交付形态与上线

- CLI `lead`（commander，全部子命令 + `--json`，含 company platforms/platform/jobs/refresh/customs）

### P7 · 真实环境验收（需用户授权）

## 2. 测试策略

| 层级 | 方式 |
|---|---|
| 单元测试 | 去重/名称归一化、匹配打分、字段 diff、状态机迁移、额度恢复判断、签名算法、区域映射、平台档案 diff、岗位生命周期、刷新到期计算、**海关名称过滤/角色分类/confidence** |
| 集成测试 | 内置 mock upstream（Fastify test server 模拟五个 client + fuma 的响应/错误码），覆盖采集→补全→平台档案/岗位→海关→解锁→事件全链路 |
| 契约测试 | 用真实 client `/openapi.json` 校验 adapter 的请求/响应 schema（不发起真实请求，离线可用；可选定时跑） |
| 只读冒烟 | 连接真实 client 的 `health/status/cities/regions`（不消耗额度、不触发采集）；单公司详情只读冒烟（Boss/智联/Ali/Mic 各 1 次） |
| 迷你流水线 | 已执行：[09 验证报告](09-上游接口与流水线验证报告.md)（5 候选/50 步/0 失败/0 额度）；实现后作为回归脚本复用 |
| 覆盖度实验 | 已完成河北四源实测：Boss 1,188 / 智联 1,261 / Ali 2,961 / Mic 5,008 → 去重 ≈9,586（见 [12](12-河北四源覆盖实测报告.md)）；实现后用 Run 覆盖度指标持续校准 |
| 遥测/性能 | 2 万家刷新容量核算；1 万公司主档列表 p95；100 万变更 `sinceSeq` 查询延迟；岗位表 200 万行查询；海关 4,000 查询/天压测；快照清理 dry-run |
| 端到端 | 真实环境小规模 Run（需授权；额度消耗透明记录） |

> 所有测试不得依赖真实隐私数据；快照/联系人样例一律脱敏。

## 3. 代码质量与工程约定

- TypeScript strict；zod 作为所有外部输入（HTTP/上游响应）的运行时校验。
- 领域逻辑（去重/匹配/diff/状态机）纯函数化，便于测试。
- 所有 DB 写操作在 repository 层，事务边界清晰；禁止在路由里拼 SQL。
- 生成物（openapi/mcp-tools/CLI 帮助）与实现同源；`npm run gen:check` 进 CI。
- 日志字段固定：`level, ts, module, event, companyId?, runId?, platform?, errorCode?, durationMs?`；PII 打码。

## 4. 风险与缓解（实施视角）

| 风险 | 缓解 |
|---|---|
| 上游页面/接口变化导致解析失败 | adapter 集中封装 + 契约校验 + 失败保留原始快照；错误快速暴露到 `/v1/sources` |
| 探迹额度被首轮耗尽 | 用户已确认接受；`waiting_quota` 可观测；预留 `LEAD_UNLOCK_DAILY_CAP` |
| 全量快照存储增长 | **brotli 压缩（实测 ≈10x）+ 哈希去重 + 90 天后冷归档（不删除，Q7）**；容量 10–20 GB/年；磁盘监控阈值；扩容而非删数据 |
| 平台刷新积压（2 万家） | 招聘每周、店铺每月全量降频；Refresh Worker 全天涓流、与采集共享限频；`/v1/status.refresh` 可观测；手动 refresh 插队 |
| 覆盖量 vs 解锁额度缺口 | 9,586 家 vs 1,500/月（≈6.4 个月）；必须优先级解锁（P0 招聘在招 → P1 认证会员 → P2 海关记录 → P3 其余），P3 只入工商库 |
| 海关模糊匹配噪声 | 名称 token 过滤 + 角色分类 + confidence；低置信度不推送；保留 matchedSample 复核 |
| fuma 海关权限/账号异常 | 任务标记 failed 并跳过；`/v1/sources` 暴露；不影响主流程 |
| 误匹配浪费额度 | USCC 优先 + 候选/置信度留痕 + rematch；后续可加阈值策略 |
| 上游登录失效 | 预检 + 跳过 + 状态暴露；不自动登录 |
| 长任务中断 | 租约 + 幂等 + 断点续跑；单轮超时收尾 |
| 真实验收消耗额度 | 单独阶段 P7 + 用户书面授权额度上限 |
