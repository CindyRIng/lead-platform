## 四、图示资产（docs/assets/）

所有图片均为**自包含生成**（无外部版权素材；示例数据为合成数据）。`*.mmd` 是 GitHub 可直接渲染的 Mermaid 语义源；`*.svg` / `*.png` 是同一内容的自包含渲染版（PNG 为 2× 清晰度，`< 2 MB`）。

| 文件 | 用途 | 引用位置 |
|---|---|---|
| `hero-banner.jpg` | 项目头图（MiniMax 生成的抽象科技插画，无文字） | README |
| `architecture-overview.{mmd,svg,png}` | 五层架构总览（上游/编排/Worker/存储/出口） | README、16 |
| `data-flow.{mmd,svg,png}` | Goal → Run → 采集 → 补全 → 主档 → 事件全链路数据流 | 16、18 |
| `pipeline-state.{mmd,svg,png}` | 公司状态机 + 解锁任务/额度队列状态机 | 16 |
| `deployment-topology.{mmd,svg,png}` | 单机 loopback 部署拓扑（端口/数据目录/systemd/下游） | README、14、15、16 |
| `render-svg.mjs` | 手工排版的 SVG→PNG 渲染脚本（Chrome headless，可复现） | — |

> 修改图示流程：先改 `*.mmd`（保持语义），若需重新出图运行 `node docs/assets/render-svg.mjs`；更新 `render-svg.mjs` 中对应布局定义，再同步 PNG/SVG。README/docs 中引用 PNG 而不是外部图床。

## 六、文档维护约定

1. **编号固定**：`00–13` 为设计基线（重大结论变更需在文档头部记录版本与变更说明）；`14–19` 为交付手册；新增文档顺延编号并更新本索引。
2. **契约同源**：REST/CLI/MCP 的字段、端点、命令以生成物为准；改契约先改代码（zod schema / definitions），再跑 `npm run gen && npm run gen:check`，最后更新 [18](18-API-CLI-MCP使用指南.md)。
3. **示例纪律**：所有示例数据必须合成（如「河北示例机械有限公司」、`91130100MA0EXAMPLE`、`138****0000`、`example.com`）；**禁止**写入真实公司、招聘人、联系人、Token、内部路径。
4. **链接纪律**：站内相对链接必须可解析；外部链接需注明用途；不使用外部版权图片。
5. **图示纪律**：`docs/assets/*.mmd` 与渲染版（`.svg/.png`）同名同源，禁止只改其一。
6. **状态标注**：设计基线与实现的差异在 [19 §17](19-项目结构与代码导读.md#17-实现状态与文档差异说明) 与相关文档中显式标注「以代码为准」，避免文档承诺超出实现。
