## 3. FR 逐条解释

> 模块路径见 §2；本节列关键表与行为，实际文件以代码为准。

### FR-1 Goal 管理（P0）｜范围入口

- **问题与行为**：把四平台/11 市/关键词固化成可复用 Goal；
  创建后 `resolvedCities` 显示 11 市，非法输入 400。上游只到地级市，县级自然覆盖，区县筛选只会查不到。
- **规则与实现**：省必填、市可选；
  Boss/智联 10 词，Ali 词仅本地过滤，Mic 空；cron 02:00；
  priority/tradeFilter 预留；一期单 Goal；
  表：`goals`/`regions`/`region_platform_map`。
- **验收/取舍**：AC-1；
  不做区县、多 Goal 并行、外贸强制过滤（BR-2）。

### FR-2 调度与触发（P0）｜每日批量 + 手动补跑

- **问题与行为**：夜间批量+手动最小可控；
  `/runs/{id}` 见 `pending→running→completed/partial` 与平台/城市/词进度，重复触发 409。
- **规则与实现**：同 Goal 不重叠；6h 超时停派发、等在飞请求、标 `partial`，已入队任务继续；
  Run 完成≠补全/解锁完成；表：`goal_runs`/`source_queries`。
- **验收/取舍**：AC-1/8；
  超时用 mock 慢上游+调小 `LEAD_RUN_MAX_HOURS`；单进程+DB 租约。

### FR-3 线索采集（P0）｜流式，不等整批

- **问题与行为**：9,586 家×匹配/详情各约 8h，整批等待会让首家公司十几小时后才补全；
  流式让 Run 未完成时公司已可查，统计含 queries/pages/leads 与覆盖度。
- **规则与实现**：Boss/智联 11 市×10 词；Ali 按省枚举+种子/矩阵；
  Mic 省+11 市并集（单省词 1,101，并集才 5,008）；
  守限频；每家即落快照+入队；登录失效/验证码跳过；
  表：`source_queries`/`raw_snapshots`/`company_sources`。
- **验收/取舍**：AC-1/2/7/17；Ali 2,961 是可发现量非全量；
  招聘仅第 1 页；口径是「活跃平台可见线索」（§6）。

### FR-4 快照与去重（P0）｜一家公司一次，每次出现留证

- **问题与行为**：下游要「公司」、审计要「平台记录」；
  Boss+智联同一公司→1 主档+2 来源，`/snapshots` 可追，合并产生 `company.merged`。
- **规则与实现**：来源 `(platform,platform_company_id)` 唯一；
  公司级 USCC→名称+同省/市→tanjiId→新建；合并软删；名称归一化只辅助；
  快照 append-only、哈希去重+brotli、永久+90 天归档（Q7）；
  表：`raw_blobs`/`raw_snapshots`/`companies`/`company_sources`。
- **验收/取舍**：AC-2/17；单测同 USCC 必并、同名不同省不并；
  名称会漏/误配，靠 rematch 兜底。

### FR-5 主档与工商补全（P0）｜权威但可纠错

- **问题与行为**：平台工商不完整，探迹权威；
  用户选「总是自动取最佳」，故详情必须含 `matchMeta`（method/confidence/candidates），匹配不到仍可查（`unmatched`）。
- **规则与实现**：USCC 精确→名称近似+同省/市+探迹分；
  低分也自动匹配但留痕；候选≤5；Ali/Mic 用英文抬头（BR-18）；
  unmatched 不耗额度、下轮重试；解锁状态以 contacts 为准；
  表：`companies`/`match_meta`。
- **验收/取舍**：AC-3 三 fixture（USCC/仅名/无结果）；
  live 只用免费 search；误配靠候选/置信度/rematch 兜底。

### FR-6 解锁队列（P0）｜FIFO 仍在，但按价值分批

- **问题与行为**：1 家 1 点；
  9,586 家 vs 月 1,500→约 6.4 个月；
  全库 FIFO 会让低价值/未核验线索先吃额度，故「FIFO」=同优先级内按发现时间。耗尽转 `waiting_quota` 不丢，恢复续跑。
- **规则与实现**：入队 `tanji_enriched`+pending；
  按 Q14 建议 `recruiting>paid_member>customs>rest`，P3 只入工商库不排解锁；执行前查额度+contacts 预检（已解锁取明文、0 点）；
  带幂等键；`QUOTA_EXHAUSTED` 不计失败；600s 轮询；不设每日上限；默认禁真实解锁；
  表：`pipeline_jobs`/`unlock_ledger`/`company_contacts`。
- **验收/取舍**：AC-4 mock 0→1、already、恢复；
  真实解锁需 Q10 授权+显式开关；当月额度可能首轮耗完（已接受）。

### FR-7 变更与事件（P0）｜下游按游标增量对齐

- **问题与行为**：下游要知道哪家/哪个字段/从什么到什么/哪次 run/哪来源；
  `/changes` 含老值/新值/来源/run/version，`/v1/changes?sinceSeq=` 返回事件+nextSeq，webhook 带 HMAC，SSE 实时。
- **规则与实现**：仅实际变化产生；同批同 version（公司内+1）；
  seq 全局单调；类型见 [02 §10.2](02-架构与数据模型.md)；
  平台字段 `platforms.<p>.<field>`、岗位聚合 `platforms.<p>.jobs`；
  HMAC 失败退避→dead；`contact.unlocked` 只带摘要；
  表：`change_events`/`webhook_subscriptions`/`webhook_deliveries`。
- **验收/取舍**：AC-5/6/12；
  至少一次投递、不保证顺序，消费者按 seq 去重。

### FR-8 对外查询（P0）｜列表看增量，详情看全貌

- **问题与行为**：同步程序要列表+游标、人工/Agent 要单公司全貌、运营要平台/海关卡片；
  列表按省/市/平台/状态/时间/词过滤，详情含来源/匹配/最近变更与 `include=platforms/customs` 卡片。
- **规则与实现**：默认 20/最大 200；游标分页；
  联系人明文仅 Bearer，列表/变更永不返回；一期不做列表平台筛选；
  `q` 是 LIKE（≥2 字符）非全文检索；
  表：`companies`/`company_sources`/`change_events`。
- **验收/取舍**：AC-5/10/11/14；
  不做 Web UI、复杂检索、列表平台筛选（预留）。

### FR-9 运行态/健康/额度（P0）｜上游失败是常态

- **问题与行为**：登录过期、验证码、额度耗尽、fuma 无权限都会发生；
  `/sources` 暴露五源健康/登录/限频/最近错误，`/quota` 看三层额度，`/status` 看队列/刷新/alerts。
- **规则与实现**：状态 `ok/degraded/session_invalid/verification_pending/unavailable`；
  采集前预检，失效跳过并记 `skippedSources`；一期只 `/status`+日志，不接外部告警；
  表：`source_health`/`quota_observations`。
- **验收/取舍**：AC-7/16；
  不自动登录、不做外部告警，人工在 client 侧恢复。

### FR-10 CLI/MCP/文档/SKILL（P0）｜同一契约三种入口

- **问题与行为**：Agent 用 MCP、人用 CLI、下游用 REST；
  三套手写必漂移。`lead status --json` 与 REST `data` 一致，MCP `lead_*` 覆盖查询/Goal/Run/事件，`/docs` 可试，OpenAPI 3.1 可导入。
- **规则与实现**：zod 做唯一契约源，生成 OpenAPI/docs/MCP/CLI help；
  CLI/MCP 代理 REST，MCP 不持 DB；
  Token 从配置读；`gen:check` 进 CI；`/docs` 自包含无真实数据；
  落点：`spec/`、`/docs`、`/mcp-tools.json`。
- **验收/取舍**：AC-9；
  不暴露所有运维动作，服务未启返回 `SERVICE_UNAVAILABLE`。

### FR-11 手工干预（P1）｜自动化的安全阀

- **问题与行为**：误匹配、平台改版、任务卡死都需人工纠错；
  rematch 重匹配留历史、unlock 提到队前、cancel 停 Run、retry 重试死信、refresh 立即刷平台/海关。
- **规则与实现**：rematch 走同一匹配/合并并产生 `company.rematched`；
  manual unlock 记 actor/原因、不破坏 FIFO 统计；
  cancel 等在飞请求；refresh 插队但受限频；P1 是优先级非二期；
  表：`pipeline_jobs`/`change_events`。
- **验收/取舍**：rematch 有 changes、manual unlock 有台账、refresh 立即生效；
  人工操作可能打乱优先级，报告须列出。

### FR-12 平台档案与招聘（P0）｜「最新」= 最近一次成功抓取

- **问题与行为**：来源证据不能回答「还在招吗、店铺什么等级」；
  详情 4 卡片含 Boss/智联岗位数/列表、Ali/Mic 会员/认证、`lastFetchedAt`/`next*RefreshAt` 与岗位 active/closed 历史。
- **规则与实现**：新公司即时 4 档案+2 岗位；招聘周/店铺月；手动插队；worker 全天共享限频；
  岗位消失 closed+closed_at、重现 active；平台状态阈值见 BR-15；
  字段 diff→`platforms.<p>.<field>`、岗位→`platforms.<p>.jobs`；列表不筛选；
  >500 条截断。2 万家每日全量约 100 小时/天，故降频；表：`company_platform_profiles`/`company_platform_jobs`。
- **验收/取舍**：AC-11/12/13；
  周/月刷新会滞后，高价值公司手动 refresh，不做实时承诺。

### FR-13 海关补全（P0，限 Ali/Mic）｜英文抬头是钥匙，样本是边界

- **问题与行为**：Ali/Mic 有英文抬头，fuma 能查提单；
  Boss/智联中文名匹配英文提单名实测 0 命中，一期不做。详情 `customs` 卡片含 totals/dateRange/topDestinations/topHs4/topBuyers/confidence/`sampled=true`。
- **规则与实现**：详情+匹配后入队；新公司即时/存量月刷/手动插队；
  `companyFlag=1/2` 各第 1 页 20 条，记 totalNum/allCount/cached/source；
  按 token 过滤全部名称字段、分出口/进口角色，unmatched 不计榜；
  confidence matched≥5 high、1–4 medium、0 none；totalNum 非精确提单量；不耗额度；
  响应永久+归档；Boss/智联不做；表：`company_customs_profiles`/`raw_snapshots`。
- **验收/取舍**：AC-14/15/16；样本有偏（每路 20 条）；
  英文名可能缩写/贸易名，保留 query_names/sampleRecords 复核；买家名可能噪声，按 confidence 过滤。

## 4. AC-1..AC-18 验收对照

### 4.1 环境分档

环境：**M** mock（内置 mock upstream+合成 fixture，0 额度，CI 可跑）；**R** 只读 live（五 client+fuma，搜索/详情免费）；
  **A** 授权消耗（Q10 上限+时间窗、`TANJI_ALLOW_UNLOCK=true`，记 before/after）。

先 M 后 R 再 A；M 未过不进 R；
  A 超限即停。预期测试：`tests/unit/*`（纯函数）、`tests/integration/*`（mock 全链路），路径以最终代码为准。
