## 1. 原始意图（用户原话摘要）

1. 可以通过 **REST / CLI / MCP** 访问 LeadPlatform。
2. 与上游几个 client 通过对方 **REST** 交互。
3. 通过 **Goal Setting** 设置获取线索的条件，目前只按区域设置，例如「河北省」= 河北省下所有地级市和县城做外贸的企业。
4. 设置目标后**自动定期**从几个上游平台（Boss 直聘 / 智联 / Ali / Mic）拉取对应地区线索；拿到线索后再通过 **Tanji** 获取目标完整工商信息与联系方式。过程**并行异步**：某平台拿到一家公司就立刻进入流水线（探迹查询→有额度解锁联系人→入库），不是等某平台全部跑完再统一探迹。额度不足则暂缓入队列，等有额度再解锁。
5. 需要合理的数据模型和外部访问接口：外部能拿到**一家公司完整的数据变更日志**，以及每家公司详细信息。

**Lead 对意图的理解**：LeadPlatform = 线索聚合 + 处理流水线 + 对外查询/事件。它不负责爬虫（采集能力在五个 client），也不负责 CRM/外呼业务编排（下游自行消费事件）。与既有架构的关系：`fuma-platform`（孚盟客保/海关能力层）、`feige-outbound-platform`（外呼能力层）、`Twenty CRM`（业务数据中枢）各司其职；LeadPlatform 决定「查谁、何时查、探迹补全与解锁、入库与广播」。

### 2.4 区域覆盖（决定 Goal 粒度）

- **四源均不支持区县级筛选**；都支持省 / 地级市级枚举。
- Boss：内置仅 50 个常用城市，`GET /v1/cities?refresh=true` 后返回 **374 个城市**（含河北全部 11 个地级市）。
- 智联：461 个城市（含河北 11 个地级市）。
- Ali：373 条省/市（河北 `CN-13` + `CN-13-1301..1311` 共 11 市）。
- Mic：32 省；**河北省市级字典完整**（11 市，英文 api_value `Hebei`）。
- 结论：Goal 区域按「省 → 地级市枚举」实现；县级企业在市级检索结果中自然覆盖。**省直辖县/雄安等特殊区划**若后续需要精确筛选，用探迹注册地址二次匹配（一期不做）。

### 2.5 身份字段与跨源去重线索

| 来源 | 可用身份字段 |
|---|---|
| boss / zhilian | 平台 companyId、公司名、城市、地址、工商文本（含 USCC，可能缺失） |
| ali / mic | 平台 companyId/account、公司名、省市、地址（无 USCC） |
| tanji | `id`（探迹企业 ID）、`name`、`uscc`（权威）、法人、地址、省市等 |

→ 去重策略：**USCC 优先；无 USCC 时用「规范化公司名 + 省/市」兜底**；与探迹匹配时优先用平台详情中的 USCC 做精确搜索，否则用公司名搜索并打分。
